## Architecture

| Rule                                                                                                                                    | Enforced by                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Choose mainstream, well-supported, LTS stacks. Justify any exotic choice at the design checkpoint.                                      | [ADR-002](../adr/002-express-prisma-postgres.md) (Express, Prisma, PostgreSQL 16). Node 20 in `.nvmrc`. React 18 in the design. `.cursor/rules/00-architecture.mdc`.                                                                         |
| Separation of concerns: layered or feature-based modules (UI / API / domain / data). No business logic in controllers or UI components. | `AGENTS.md`. `.cursor/rules/00-architecture.mdc`, `.cursor/rules/20-api.mdc`, `.cursor/rules/30-web.mdc`.                                                                                                                                    |
| Twelve-Factor App: config in environment variables, stateless processes, dev/prod parity, logs as event streams.                        | `.env.example` and `apps/api/src/config/env.ts` (Zod at startup). Pino logger and ESLint `no-console`. `docker-compose.yml` and `apps/api/Dockerfile`. Statelessness itself is agreed and has no separate CI check.                          |
| APIs: REST with an OpenAPI spec (or GraphQL with a schema). Consistent error format. Versioned (`/v1`). Pagination for lists.           | `apps/api/openapi/openapi.yaml`. CI **OpenAPI contract check**. `apps/api/src/routes/v1.ts`. Error shape in `.cursor/rules/00-architecture.mdc`. `packages/shared/src/pagination.ts`.                                                        |
| Data: migrations under version control. Never edit production schema by hand. Indexes on query paths. Backups for persistent stores.    | `apps/api/prisma/migrations/`. CI **Migrate** and **Migration drift check**. Backups are an accepted gap on the free database until Checkpoint 5 ([R16](../design.md#reliability-and-operations), [deployment](../05-deployment/README.md)). |
| Dependencies: pin versions with a lockfile. Minimal dependencies. No abandoned packages.                                                | `package-lock.json` and CI `npm ci`. "Minimal" and "not abandoned" are review rules. No CI job scores them.                                                                                                                                  |
| Record significant decisions as ADRs in `docs/adr/`.                                                                                    | [docs/adr](../adr/README.md), ADR-001 through ADR-012. No CI job requires a new ADR.                                                                                                                                                         |
| Design for observability: health check, structured logs, metrics, and error tracking.                                                   | `GET /v1/health` (`apps/api/src/routes/health.routes.ts`). Pino request logs. Metrics and Sentry are [NFR-OPS-02](../design.md#4-requirement-traceability-matrix). Milestone 1 parses `SENTRY_DSN` and does not wire Sentry yet.             |

## Coding style

| Rule                                                                                                                                       | Enforced by                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Follow each language's official style guide. For this stack: TypeScript strict.                                                            | `tsconfig.base.json` `strict: true`. `eslint.config.js` uses `typescript-eslint` strict type-checked configs. CI **Lint** and **Type-check**. `.cursor/rules/10-standards.mdc`. |
| Enforce with tools, not reviews. Formatter and linter run in pre-commit and CI. Zero lint errors to merge.                                 | Prettier and ESLint as in the table at the top. `.husky/pre-commit`. CI **Lint** and **Format check**. `.cursor/rules/10-standards.mdc` (zero warnings).                        |
| Prefer TypeScript over JavaScript. Strict type checking wherever it exists.                                                                | Application code is TypeScript. Tooling config stays JavaScript (`eslint.config.js`, `prettier.config.js`, `commitlint.config.js`).                                             |
| Clean Code and SOLID: small single-purpose functions, meaningful names, no dead code, no magic numbers, DRY without premature abstraction. | `AGENTS.md` and `.cursor/rules/10-standards.mdc`. ESLint flags unused variables. The rest is review guidance, not a CI rule.                                                    |
| Naming: camelCase for values and functions, PascalCase for types and components, UPPER_SNAKE for constants. Descriptive file names.        | Agreed. No dedicated naming linter beyond TypeScript and ESLint defaults. The design also maps database snake_case to API camelCase.                                            |
| Handle errors explicitly. Never swallow exceptions. Structured logging. No `console.log` in production code.                               | ESLint `no-console: error`. Pino in `apps/api/src/lib/logger.ts`. `.cursor/rules/10-standards.mdc` and `.cursor/rules/20-api.mdc`.                                              |
| `.editorconfig` in every repo. UTF-8, LF, trailing newline.                                                                                | `.editorconfig`.                                                                                                                                                                |
| Comments explain why, not what. Public APIs have doc comments.                                                                             | Agreed. No ESLint rule in `eslint.config.js` requires doc comments.                                                                                                             |

## Security

| Rule                                                                                                                                    | Enforced by                                                                                                                                                                                                                                                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Address OWASP Top 10 (web) and OWASP ASVS Level 1 at minimum.                                                                           | Design [section 6, Security](../design.md#security). No ASVS scanner in CI.                                                                                                                                                                                                                              |
| Never commit secrets. Use environment variables or a secrets manager. Secret scanning in CI.                                            | `.gitleaks.toml`, `.husky/pre-commit`, CI **Secret scan**. `.env.example` placeholders. `.gitignore` ignores `.env`. The seed refuses an empty or weak `ADMIN_PASSWORD` (recorded in the README and in Milestone 1).                                                                                     |
| Validate and sanitize all input on the server. Parameterized queries only. Encode output to prevent XSS.                                | `.cursor/rules/10-standards.mdc` and `.cursor/rules/20-api.mdc`. Zod schemas in `packages/shared`. Prisma. [NFR-SEC-03](../design.md#4-requirement-traceability-matrix) is a [Milestone 5](../03-implementation/m5-hardening.md) exit criterion. No CI job scans for concatenated SQL.                   |
| Auth uses proven libraries. Hash passwords with bcrypt or argon2. HTTPS. Secure, HttpOnly, SameSite cookies. CSRF protection.           | [ADR-003](../adr/003-jwt-refresh-cookie.md) and [ADR-004](../adr/004-same-origin-rewrite.md). `packages/shared/src/password.ts` (8+ characters, a letter, and a number). Milestone 1 seeds bcrypt cost 12. Sign-up, login, and cookies are [Milestone 2](../03-implementation/m2-auth.md).               |
| Least privilege for services, tokens, and database users. Role checks on every protected endpoint.                                      | [FR-AUTH-05](requirements.md). `.cursor/rules/00-architecture.mdc`. The route checks are Milestone 2 work.                                                                                                                                                                                               |
| Dependency vulnerability scanning in CI. No known high or critical vulnerabilities at release.                                          | CI **Dependency audit** via `scripts/audit-deps.mjs`. `CONTRIBUTING.md` documents the one allowlisted advisory, `GHSA-fc5q-39xc-vjpf` (picomatch, dev tooling, no patched release). No Dependabot config file is in the repo. [NFR-SEC-05](../design.md#4-requirement-traceability-matrix).              |
| Security headers (CSP, HSTS, `X-Content-Type-Options`). Rate limiting on auth and public endpoints.                                     | Milestone 1 added helmet and the rate limiter (`apps/api/src/middleware/rate-limit.ts`). Limits are restated in `.cursor/rules/20-api.mdc` (10/min auth, 100/min public). [NFR-SEC-02](../design.md#4-requirement-traceability-matrix) and [NFR-SEC-04](../design.md#4-requirement-traceability-matrix). |
| Protect personal data: collect the minimum, encrypt in transit and at rest, and follow GDPR and India DPDP principles where they apply. | Agreed. The design stores passwords only as bcrypt hashes and uses HTTPS and TLS to PostgreSQL. No separate privacy-control file or CI job.                                                                                                                                                              |

## Testing

| Rule                                                                                                           | Enforced by                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Test pyramid: many unit tests, fewer integration tests, a few end-to-end tests of critical flows.              | `.cursor/rules/40-testing.mdc`. Vitest unit and API integration tests. Playwright is scaffolded in `apps/web` and is not a CI job (`apps/web/e2e/README.md`).                                                                                                                                                                         |
| At least 80% line coverage on business logic. Coverage in CI. New code must not lower coverage.                | Line threshold 80 in `packages/shared/vitest.config.ts`, `apps/api/vitest.config.ts`, and `apps/web/vite.config.ts`. Web branch threshold is 70, recorded as a Milestone 1 deviation. CI **Test with coverage**. [NFR-QUAL-01](../design.md#4-requirement-traceability-matrix).                                                       |
| Default tools for this stack: Vitest, Testing Library, and Playwright.                                         | Design section 4 names those tools. Jest is the org default alternative and is not the runner here.                                                                                                                                                                                                                                   |
| Every acceptance criterion has at least one automated test. Every bug fix adds a regression test.              | `AGENTS.md`, `.cursor/rules/10-standards.mdc`, `.cursor/rules/40-testing.mdc`. The Checkpoint 4 matrix in [testing](../04-testing/README.md) is still pending, so CI does not yet check each ID.                                                                                                                                      |
| Tests are deterministic, isolated, and fast. No reliance on external live services (mocks or test containers). | API integration tests use the CI PostgreSQL service, not a mock of the database (`.cursor/rules/40-testing.mdc`).                                                                                                                                                                                                                     |
| All tests pass in CI before merge. Flaky tests are fixed or quarantined with an issue.                         | CI **Test with coverage**. No quarantine list is in the repo.                                                                                                                                                                                                                                                                         |
| A basic performance check for key endpoints and pages, and an accessibility scan (axe), before release.        | Planned as [NFR-PERF-01](../design.md#4-requirement-traceability-matrix), [NFR-PERF-02](../design.md#4-requirement-traceability-matrix), and [NFR-A11Y-01](../design.md#4-requirement-traceability-matrix). The CI workflow has no autocannon, Lighthouse, or axe step. `eslint-plugin-jsx-a11y` recommended rules run on `apps/web`. |
